# 三面演示说明

## 1. 一句话定位

这不是重新建设客服系统，而是选择投诉处理中最耗时、最需要证据、又不适合完全自动化的核查环节，做成一个可以嵌入现有工单系统的 AI 辅助模块。

## 2. 建议时长

总时长 5～8 分钟：

1. 业务背景和范围：1 分钟。
2. 三角色业务演示：3～4 分钟。
3. 技术设计和风险控制：2 分钟。
4. 限制与下一步：30 秒。

## 3. 演示前准备

```sh
scripts/demo.sh up
scripts/demo.sh status
```

打开 http://127.0.0.1:8088 。优先使用 `DEMO-002` 解释授权缺失，使用 `DEMO-003` 解释金额不一致。需要演示新投诉流转时使用 `DEMO-001`。

如果没有配置讯飞凭据，应明确说明本次展示的是“模型不可用也不阻塞人工”的降级路径，并同时展示仓库中已经留存的真实联调脱敏记录。

## 4. 演示流程

### 第一步：客服受理

- 使用客服身份进入新投诉。
- 点击提交后立即看到工单已进入投诉处理队列。
- 讲解重点：宿主流转先完成，AI 任务异步执行，模型失败不能影响原流程。

### 第二步：投诉处理专员

- 切换到投诉处理专员，页面路由和工单保持不变。
- 展示账单、订购、授权材料和证据快照。
- 展示规则发现和 AI 建议中的证据引用。
- 修改摘要或建议后确认/退回。
- 讲解重点：AI 只准备材料，人负责最终核查；系统没有退款执行接口。

### 第三步：质检审计

- 切换质检身份，打开只读时间线。
- 展示事件 ID、工单版本、模型、Prompt、耗时、错误类型和 Trace ID。
- 展示 AI 原始意见与人工修改结果分开保存。
- 讲解重点：审计角色不是第二审批节点，只负责追溯和抽检。

## 5. 最值得强调的设计

- AI 最有价值的环节不一定适合完全自动化。
- 业务事实来自宿主系统，规则由代码执行，AI 负责理解与整理。
- AI 引用的证据必须属于本轮不可变快照，不能凭空生成依据。
- 工单进入队列后默认异步准备，专员打开时直接使用结果。
- 模型失败、超时、非法输出都安全转人工，不阻塞投诉处理。
- 人工确认、版本控制和审计在数据库事务中保持一致。

## 6. 面试口径

可以说：

- “这是一个可运行、可验证的小业务闭环。”
- “已使用合成数据完成讯飞 MaaS 单样本真实联调。”
- “已考虑角色权限、审计、证据追溯、失败兜底和低侵入集成。”

不要说：

- “已经实现真实运营商生产接入。”
- “AI 准确率很高”或“已经提升多少效率”。
- “审计记录不可篡改”或“已经满足等保要求”。
- “系统可以自动判断并执行退款。”

## 7. 下一步规划

1. 与真实业务人员确认授权凭据形态、资费规则和处理口径。
2. 建立约 20 条人工标注合成样本，评测提取、缺失识别、修订率和总耗时。
3. 接入宿主统一认证、租户和工单级数据权限。
4. 对接真实账单、订购和授权服务，并补充超时、限流和监控告警。
