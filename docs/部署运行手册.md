# 部署运行手册

## 1. 环境要求

- Docker Engine
- Docker Compose v2
- 可用端口：前端默认 `8088`，MySQL 默认 `13307`

直接开发时另需 JDK 17、Maven 3.9+、Node.js 22.12+ 和 npm。

## 2. 一键启动

在仓库根目录执行：

```sh
scripts/demo.sh up
```

脚本首次运行会创建被 Git 忽略且权限为 600 的 `docs/TelecomAIPrecheck/.env`，自动生成数据库和演示账号随机密码，并构建启动：

- MySQL 8.4
- Spring Boot 后端
- Vue 3 静态页面与 Nginx

访问：http://127.0.0.1:8088
健康检查：http://127.0.0.1:8088/actuator/health

## 3. 常用命令

```sh
scripts/demo.sh status   # 查看三个服务状态
scripts/demo.sh logs     # 跟踪前后端日志
scripts/demo.sh build    # 只构建镜像
scripts/demo.sh stop     # 停止并删除容器，保留 MySQL 数据卷
```

不要把 `down -v` 当作日常停止命令；它会删除数据库卷和演示历史。

## 4. 环境变量

| 变量 | 默认/说明 |
| --- | --- |
| `FRONTEND_PORT` | 对外统一入口，默认 8088 |
| `MYSQL_PORT` | MySQL 宿主端口，默认 13307 |
| `RELEASE_TAG` | 后端和前端镜像标签，本地默认 `local` |
| `DB_USERNAME`、`DB_PASSWORD` | 业务数据库账号 |
| `MYSQL_ROOT_PASSWORD` | MySQL root 密码 |
| `DEMO_ONE_CLICK_LOGIN` | 是否启用演示岗位登录，默认 true |
| `DEMO_*_PASSWORD` | 四类演示/服务身份密码 |
| `XFYUN_API_KEY` | 讯飞 MaaS Key；不配置时安全转人工 |
| `XFYUN_MODEL` | 已开通的模型 ID，例如 `spark-x2.5` |
| `XFYUN_TIMEOUT_MS` | 模型超时，默认 30000 |
| `PRECHECK_TASK_MAX_ATTEMPTS` | 异步任务最大执行次数，默认 3 |
| `PRECHECK_TASK_RETRY_DELAY_SECONDS` | 重试间隔，默认 30 秒 |

密钥和密码不能提交到 Git，也不能使用 `VITE_` 前缀暴露给浏览器。

## 5. Compose 网络

只有 Nginx 前端和 MySQL调试端口映射到宿主机。后端仅在 Compose 内部网络监听 `8080`，浏览器通过 Nginx 的 `/api` 和 `/actuator` 代理访问，避免本机 8080 端口冲突。

## 6. GitHub Actions 与版本标签

工作流不会在普通 push 时运行。触发方式：

```sh
git tag v0.1.0
git push origin v0.1.0
```

也可以在 GitHub Actions 页面手动运行 `workflow_dispatch`。

版本标签工作流执行：

1. 使用真实 MySQL 运行后端测试并打包 JAR。
2. 运行前端单元测试和生产构建。
3. 运行浏览器业务流程测试。
4. 构建带当前 Git 标签的前后端镜像。
5. 使用 BuildKit/GitHub Actions 缓存加速后续镜像构建。
6. 启动整栈 Compose 并验证页面和后端健康检查。

当前工作流只构建和验收镜像，不推送 Docker Hub 或 GHCR。

## 7. 故障排查

| 现象 | 检查项 |
| --- | --- |
| 首次构建较慢 | Docker 内首次下载 Maven/npm 依赖；后续使用缓存 |
| 前端 502 | `scripts/demo.sh status` 确认 backend 是否健康 |
| 后端启动失败 | 检查数据库密码是否与已有命名卷一致 |
| 模型未配置 | 设置 `XFYUN_API_KEY` 和 `XFYUN_MODEL`；否则按设计转人工 |
| 页面登录接口不存在 | 确认 `DEMO_ONE_CLICK_LOGIN=true` |
| 端口占用 | 修改 `.env` 中 `FRONTEND_PORT` 或 `MYSQL_PORT` |
