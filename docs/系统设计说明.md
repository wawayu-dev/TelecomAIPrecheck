# 系统设计说明

## 1. 总体架构

```text
浏览器
  │
  ▼
Nginx / Vue 3
  │  /api、/actuator 反向代理
  ▼
Spring Boot 3 / Spring Security / MyBatis
  ├─ TicketContextProvider ──► 模拟或真实宿主业务系统
  ├─ EvidenceVerifier ───────► 确定性证据规则
  ├─ Spring AI Client ──────► 科大讯飞星辰 MaaS
  ├─ ResultValidator ───────► 结构与证据引用校验
  └─ MySQL 8 / Flyway ──────► 任务、快照、人工结果、审计
```

模块不持有客户、账单、订购和原始工单主数据，只保存完成核查所需的证据快照和处理记录。

## 2. 后端模块

| 模块 | 职责 |
| --- | --- |
| `context` | 宿主数据契约和证据结构 |
| `adapter` | 合成数据适配器及模拟宿主流转 |
| `precheck` | 异步任务、规则核验、模型调用、输出校验和持久化 |
| `review` | 人工确认、乐观并发控制和审计时间线 |
| `security` | 角色权限、演示身份、Session 和 CSRF |
| `web` | Trace ID、统一错误响应和上下文 API |

## 3. 异步任务设计

宿主事件接口只负责把任务可靠写入 MySQL，然后返回 `202`。进程内线程池用于及时执行，数据库是任务恢复依据，不把内存队列当作唯一消息来源。

任务状态：

```text
QUEUED ─► RUNNING ─► COMPLETED
              │
              ├─ 临时失败且未耗尽次数 ─► RETRY_WAIT ─► RUNNING
              └─ 永久失败或耗尽次数 ───► FAILED
```

业务状态：

```text
ANALYZING ─► PENDING_REVIEW ─► REVIEWED
```

- `(event_source, ticket_id, ticket_version)` 保证同一业务版本幂等。
- `(event_source, event_id)` 防止事件 ID 被重复用于其他业务版本。
- 模型调用和宿主查询不占用长数据库事务。
- `attemptCount` 防止已被恢复的旧线程覆盖新尝试结果。
- 运行超过五分钟的任务由恢复器转为重试或失败转人工。

## 4. AI 安全边界

1. 业务事实来自宿主系统，而不是模型记忆。
2. 证据规则由 Java 代码先执行，规则结果随上下文发送给模型。
3. 模型只能输出投诉类型、争议金额、摘要、证据 ID 和白名单建议。
4. JSON 开启未知字段、尾随内容、重复键和类型强转限制。
5. 引用证据必须存在于本轮快照，重复或虚构引用直接判为失败。
6. 授权不完整时由后端覆盖为中性摘要，避免模型认定违规。
7. 模型输出不包含退款金额、违规认定或外部执行动作字段。

## 5. 数据模型

| 表 | 说明 | 关键字段 |
| --- | --- | --- |
| `ai_precheck_run` | 一轮核查和异步任务 | 工单、事件版本、状态、模型、Prompt、耗时、错误、行版本 |
| `ai_precheck_evidence_snapshot` | 本轮不可变业务材料快照 | `run_id`、上下文 JSON |
| `ai_precheck_review` | 人工核查结果 | 决定、摘要、建议、依据、操作人、版本 |
| `ai_precheck_audit` | 追加式业务审计 | 动作、前后状态、模型、工单版本、Trace ID、错误类型 |

`ai_precheck_review` 与快照均通过 `run_id` 关联预审轮次。审计表没有业务修改或删除接口，但这不等于生产级防篡改存证。

## 6. 权限设计

| 能力 | OPERATOR | REVIEWER | AUDITOR | HOST |
| --- | :---: | :---: | :---: | :---: |
| 读取宿主上下文 | ✓ | ✓ | ✓ | — |
| 模拟宿主流转 | ✓ | — | — | — |
| 查询核查结果 | — | ✓ | ✓ | — |
| 人工确认、重试 | — | ✓ | — | — |
| 查询审计时间线 | — | ✓ | ✓ | — |
| 投递内部事件 | — | — | — | ✓ |

生产接入应以宿主统一身份认证替换演示账号，并补充租户、组织、数据域和工单级授权。

## 7. 数据安全与审计

- API Key 和密码只通过环境变量注入。
- 模型供应商错误原文和未经校验的模型输出不落库、不返回前端。
- 人工输入中的手机号、身份证号和邮箱在保存前脱敏。
- 每个请求生成或透传 Trace ID；错误响应只返回受控错误码。
- 审核状态更新、人工结果和审计记录在一个事务中提交。

## 8. 集成扩展点

真实运营商系统需要实现：

```java
public interface TicketContextProvider {
    TicketContext getContext(String ticketId);
}
```

适配器负责调用已有账单、订购和授权服务，并转换为稳定契约。AI 核心流程不依赖具体 CRM 表结构或接口地址。

当前未实现：消息队列、分布式任务租约、多租户隔离、集中式密钥管理、生产监控告警和防篡改审计平台。
