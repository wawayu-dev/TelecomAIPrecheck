## 2. 产品目标与业务痛点假设

目标：让现有工单处理人员拿到一份可以核查、修改和交接的扣费争议预审材料。

依据公开资料推导的待验证痛点：投诉口语化、证据跨业务来源、授权记录可能缺失或无法查询、交接时重复整理、模型结论缺乏事实引用。这些是产品假设，尚无访谈或现场计时证据。

| 角色 | 任务 | 模块提供的价值假设 |
| --- | --- | --- |
| 客服／投诉处理人员 | 阅读投诉、定位争议业务与账期、收集资料 | 减少重复整理，提供结构化摘要和证据列表 |
| 人工审核员 | 核对事实、修正建议、确认或驳回 | 保留最终意见控制权，明确事实与建议来源 |
| 宿主系统开发／运维人员 | 对接主数据、身份、权限与部署 | 通过稳定接口接入，避免改动核心业务表 |
| 业务监督人员 | 追溯操作和依据 | 查询状态变化、证据快照、模型版本与人工意见 |

价值验证放在 Issue #5：约 20 条人工标注合成样本，记录字段提取、证据缺失、人工修订、调用失败及耗时；有条件再比较人工与 AI 辅助总处理时间。当前没有准确率、效率或收益数据。

## 3. MVP 用户故事与范围

- 处理人员从已有工单进入模块，不重复输入投诉和账单。
- 系统保留证据快照，先由代码检查关联和完整性，再由 AI 整理摘要与建议。
- 审核员能看到可核验的证据引用，修订、确认或驳回；模型失败也可人工处理。
- 每轮结果可追溯到来源、模型与 Prompt 版本、人工操作和 Trace ID。

不做：完整 CRM、自动退费、套餐变更、真实订购修改、多 Agent、向量数据库、复杂审批流、生产运营商认证或合规承诺。

## 4. Issue #1 交付边界

本阶段实现：Java 17 + Spring Boot 工程、Spring AI 基础类型依赖（不启用模型客户端）、MyBatis/MySQL 依赖、Vue/Vite 联调页、只读宿主契约、三组模拟证据、环境配置、健康检查、异常处理和 CI。

不在本阶段实现：AI 接口调用、业务证据规则判定、预审持久化、审核权限或状态机、业务审计、正式预审页面、应用镜像发布。只读页面的证据状态是适配器提供的获取状态，不是 AI 判断。
