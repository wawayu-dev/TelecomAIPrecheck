# 接单即用的 AI 核查工作台与宿主业务集成

## 业务入口

正常流程不再从页面点击“生成 AI”。模拟宿主由 OPERATOR 在工单详情执行“流转至投诉队列”，后端先完成宿主流转，再投递已有的投诉队列事件；AI 服务失败不会回滚宿主流转。真实宿主继续使用 Issue #6 的内部事件契约。

Vue Router 路由保持 `/host/tickets/{ticketId}/precheck`。页面打开后并行读取：

- `GET /api/tickets/{ticketId}/context`：原始投诉、账单、订购与授权凭据；
- `GET /api/ai-prechecks/tickets/{ticketId}/current`：由后端根据 `current_result` 判定的当前有效核查轮次；
- `GET /api/ai-prechecks/tickets/{ticketId}`：历史轮次，允许查看已过期版本。

页面对 `ANALYZING` 任务只轮询单轮详情接口，不重复读取完整工单和历史。`QUEUED/RUNNING/RETRY_WAIT` 均不遮挡左侧原始工单。工单新版本到达后，旧轮次显示“已过期”，不可确认或重试。

## 人工确认与失败兜底

REVIEWER 在同一个工作台修正摘要、处理建议和核查意见，继续使用原审核接口、版本号和乐观锁。`CONFIRMED` 仅代表核查材料已确认；不执行退费，不写宿主最终业务结论，也不要求额外第二人审批。`MANUAL_REVIEW` 保留转投诉专员或主管进一步核实的扩展语义。

自动任务最终失败时：

- 原始工单和证据仍可查看；
- REVIEWER 可以直接填写人工核查材料；
- OPERATOR 或 REVIEWER 可调用 `POST /api/ai-prechecks/{runId}/retry`，携带 `expectedVersion` 授权原任务重新入队；
- 只有当前工单版本、`FAILED/PENDING_REVIEW` 且版本匹配的自动任务可以重试，避免旧页面覆盖新状态。

人工触发接口仍为调试与异常排查保留，但不出现在工作台主操作区。

## 后端统一审计时间线

`GET /api/ai-prechecks/{runId}/timeline` 仅允许 REVIEWER、AUDITOR 读取。后端把追加式审计事件与已有 AI 原始结果、人工确认结果聚合为时间线项，前端不自行拼接审计含义。时间线展示：

- 宿主事件接收、任务开始、自动重试、人工授权重试、完成或失败；
- 事件 ID、工单版本、Trace ID、模型、Prompt、耗时、错误类型和证据快照 ID；
- 人工确认事件中的 AI 原始摘要/建议与专员确认后的摘要/建议/意见。

质检审核人员仍是只读身份，只负责过程审计，不作为每张工单的串行审批节点；原 `/audit` 接口继续保留兼容性。

## 模拟宿主权限

| 身份 | 演示职责 |
| --- | --- |
| OPERATOR | 客服受理人员；模拟工单创建与流转；查看工单与任务；必要时授权失败任务重试 |
| REVIEWER | 投诉处理专员；修正、确认或退回核查材料；可授权失败任务重试 |
| AUDITOR | 质检审核人员；只读审计工单材料、证据快照和操作时间线；不审批工单 |
| HOST | 真实内部事件接口的服务身份，不进入业务页面 |

模块继续沿用宿主 Session、角色映射和 CSRF，不增加第二套登录。

## 三面现场演示（约 2–3 分钟）

1. **客服受理：** 客服受理人员（OPERATOR）打开 DEMO-001，模拟创建工单并流转至投诉处理队列；接口立即返回，页面显示后台处理中并可同时查看原始投诉和证据。
2. **专员确认：** 切换 REVIEWER，直接看到已经准备好的材料，修正摘要与建议后确认；强调“材料确认不等于批准退费”。
3. **质检审计：** 切换质检审核人员（AUDITOR），以只读方式展开时间线，展示宿主事件、模型和耗时、证据快照、AI 原文与人工修改结果。该角色不参与工单串行处理。

异常兜底可使用未配置 MaaS 的本地环境：AI 很快进入失败状态，原工单仍可人工填写，并可演示“授权重新执行”。DEMO-002 用于缺少授权凭据，DEMO-003 用于账单与订购金额不一致。

命令行演示 `python3 scripts/demo-smoke.py` 也走同一宿主流转与异步轮询链路。
