# 产品需求说明

## 1. 产品定位

Telecom AI Precheck 是嵌入运营商既有投诉工单系统的 AI 核查辅助模块。MVP 只处理增值业务扣费争议中的材料准备环节：读取工单与证据、执行确定性规则核验、生成 AI 辅助意见、交由投诉处理专员确认，并保留完整审计记录。

模块不重新建设 CRM、呼叫中心或完整工单平台，不执行退费、套餐变更、停复机等生产操作。

## 2. 目标与非目标

### 2.1 目标

- 工单进入投诉处理队列后自动准备核查材料，减少人工等待和重复点击。
- 聚合账单、订购记录和授权凭据，以不可变快照支持后续追溯。
- 将业务事实、确定性规则、AI 建议和人工结论分开保存。
- 在证据缺失、模型超时或输出异常时安全转人工，不阻塞原工单流转。
- 通过角色权限、状态约束、操作审计和 Trace ID 展示 ToB 系统基本要求。

### 2.2 非目标

- 不判断最终是否退款，不调用真实资金或业务变更接口。
- 不实现完整客户、工单、账单和订购主数据系统。
- 不承诺生产级统一认证、多租户隔离、防篡改存证或等保合规。
- 不以三组合成样本证明准确率、效率或经济收益。

## 3. 用户角色

| 角色 | 系统角色 | 核心任务 | 权限边界 |
| --- | --- | --- | --- |
| 客服受理人员 | `OPERATOR` | 登记投诉并提交至投诉处理队列 | 不查看 AI 核查结果和审计日志 |
| 投诉处理专员 | `REVIEWER` | 查看证据与 AI 建议，修订并确认或退回 | 不能执行退款；不能修改原始证据快照 |
| 质检审核人员 | `AUDITOR` | 只读查看核查结果、证据和操作时间线 | 不参与业务确认，不修改数据 |
| 宿主系统 | `HOST` | 投递工单进入投诉队列事件 | 只能访问内部事件接口 |

## 4. 核心业务流程

1. 客服在宿主系统完成投诉登记并将工单流转至投诉处理队列。
2. 宿主系统发送包含事件 ID、工单 ID 和工单版本的事件。
3. 模块先持久化任务并立即返回，不等待证据查询或模型响应。
4. 后台任务读取工单、账单、订购和授权材料，保存本轮证据快照。
5. 代码执行证据关联、缺失项和金额一致性检查。
6. 讯飞模型基于投诉、证据和规则结果生成结构化辅助意见。
7. 后端校验输出结构及证据引用；失败时记录受控错误并转人工。
8. 投诉处理专员查看材料，修订摘要与建议后确认或要求补充材料。
9. 质检审核人员通过只读时间线追溯事件、模型、证据和人工修改。

## 5. 功能需求

### FR-01 宿主上下文读取

- 根据 `ticketId` 读取投诉原文、客户引用、账单、订购和授权材料。
- 区分 `AVAILABLE`、`NOT_FOUND` 和 `UNAVAILABLE`，不得把查询失败解释为未授权。

### FR-02 事件驱动预处理

- 工单进入投诉处理队列后自动创建任务。
- 同一来源、工单和版本只能创建一轮任务。
- 同一事件 ID 不能用于不同工单版本。
- 新工单版本到达后，旧结果保留但标记为非当前版本。

### FR-03 证据核验与 AI 建议

- 检查证据 ID 唯一性、业务关联、授权缺失和金额差异。
- AI 只能返回白名单业务字段，不能返回执行退款等动作。
- AI 引用的证据 ID 必须来自本轮快照。
- 授权材料不完整时，系统必须使用中性表述并建议人工核验。

### FR-04 人工确认

- 专员可修订核查摘要、处理建议和核查依据。
- 决定包括 `CONFIRMED` 和 `REJECTED`。
- 通过版本号和条件更新防止重复或并发覆盖。
- AI 失败时仍允许专员直接填写人工核查材料。

### FR-05 审计追溯

- 记录任务入队、开始、重试、完成、失败和人工确认。
- 记录操作者、状态变化、工单版本、模型、Prompt、耗时、错误类型和 Trace ID。
- 审计接口只读；原始 AI 结果、人工结果和证据快照相互独立。

## 6. 业务规则

- 账单存在不代表收费合理；订购存在不代表授权有效。
- 授权查询失败和授权不存在是不同事实。
- 金额不一致只提示核实计费依据，不自动认定多扣费。
- `CONFIRMED` 仅表示核查材料已经由人员确认，不表示已退款或投诉已最终办结。
- 模型失败不能回滚宿主系统已经完成的工单流转。

## 7. 非功能要求

- 数据最小化：演示只使用合成数据，日志不输出密钥或不必要的投诉原文。
- 可恢复：临时失败有限重试；进程中断任务可扫描恢复。
- 可审计：审核状态更新、人工结果和审计写入保持事务一致。
- 可集成：通过 `TicketContextProvider` 隔离宿主数据来源。
- 可部署：使用 Docker Compose 一键启动 MySQL、后端与前端/Nginx。

## 8. MVP 验收条件

- 客服提交后能够生成异步核查任务。
- 专员打开工单时能够查看原始材料、当前核查结果和历史版本。
- 缺失授权、金额不一致和模型失败都有明确且安全的展示。
- 专员可以确认或退回，重复提交返回冲突。
- 审计角色能够只读查看完整时间线。
- 未授权角色、缺少 CSRF 或伪造身份的写请求被拒绝。
