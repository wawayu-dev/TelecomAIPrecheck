# 测试验收说明

## 1. 测试范围

| 层次 | 工具 | 覆盖内容 |
| --- | --- | --- |
| 后端单元测试 | JUnit 5 | 证据规则、结果校验、模型协议和异常映射 |
| 后端集成测试 | Spring Boot Test + MySQL 8 | Flyway、持久化、事务、权限、并发、异步恢复 |
| 前端组件测试 | Vitest + Vue Test Utils | 三角色页面、请求状态、冲突处理、XSS 和草稿保留 |
| 浏览器流程 | Playwright Chromium | 登录、工单流转、人工核查、审计和窄屏布局 |
| 整栈验收 | Docker Compose + HTTP smoke | 镜像、健康检查、Nginx 代理和持久化闭环 |

真实讯飞调用由显式开关控制，不在每次自动化构建中产生付费请求。

## 2. 核心验收场景

### 场景 A：完整证据

- 工单：`DEMO-001`
- 账单、订购和授权均存在。
- 验证结构化结果只能引用本轮证据。
- 人工仍需确认，系统不自动执行退款。

### 场景 B：授权缺失

- 工单：`DEMO-002`
- 授权查询成功但未找到记录。
- 必须提示进一步核验，不能据此认定违规扣费。

### 场景 C：金额不一致

- 工单：`DEMO-003`
- 账单 30 元、订购月费 20 元。
- 必须提示核实计费依据，不能自动计算退款金额。

### 场景 D：模型不可用

- 不配置模型凭据或模拟超时/非法响应。
- 工单材料与失败记录保留，任务进入人工待审核。
- 专员仍可完成纯人工核查。

### 场景 E：并发和幂等

- 重复宿主事件只返回原任务。
- 同一事件 ID 绑定其他版本返回冲突。
- 两个审核请求只有一个成功。
- 旧版本和过期页面不能覆盖当前结果。

### 场景 F：权限和审计

- 匿名、越权、缺少 CSRF 和伪造身份请求被拒绝。
- 审核结果与审计写入必须同时成功或同时回滚。
- 质检角色只能读取，不能提交业务结果。

## 3. 发布验收标准

- 后端、前端、浏览器和 Compose 四个 GitHub Actions Job 全部成功。
- 三个 Compose 服务健康，统一入口 `/actuator/health` 返回 `UP`。
- HTTP smoke 完成工单流转、任务结束、人工确认和审计查询。
- 仓库不包含真实密码、模型 Key 或真实客户数据。
- README、API 和部署文档与当前接口、端口和触发条件一致。

## 4. 当前验证结论

- 已完成一次 `spark-x2.5` 合成工单真实联调，并保存脱敏记录。
- 已验证模型未配置时的失败转人工、持久化和审计闭环。

- 单次真实模型成功不能代表准确率、稳定性或平均时延。
- 不应宣称已经通过等保、信创、密码测评或运营商终验。
- 不应宣称已实现生产级多租户、统一认证或不可篡改审计。
